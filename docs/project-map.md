## Цель

Приложение-плейсмент для Bitrix24: конвертирует текст между Bitrix24 BBCode,
Markdown и HTML (**Markdown — опорный формат**), с живым превью и загрузкой/
сохранением текста объектов портала (задачи, CRM-комментарии, посты Живой ленты)
прямо из тулбара. Чистый статический SPA (`nuxt generate`), без серверной части;
работает в двух режимах — standalone-сайт и iframe-плейсмент внутри портала.

## Архитектура (обзор)

Три формата, Markdown — пивот: **BBCode ↔ MD ↔ HTML**, каждая конвертация идёт
через MD. Чистое ядро — в `app/utils/*` (покрыто тестами), реактивные обёртки —
в `app/composables/*`, UI — в компонентах.

| Слой | Файлы | Роль |
|---|---|---|
| Парсер BBCode | `app/utils/bbcode-parser.ts` | рекурсивный спуск → AST (`KNOWN_TAGS` — закрытый набор) |
| Конвертеры | `bbcode-to-md.ts`, `md-to-bbcode.ts`, `md-to-html.ts`, `html-to-md.ts` | чистые функции между форматами (`markdown-it` / `htmlparser2`) |
| Санитайзер | `sanitize-html.ts` | allow-list перед выводом в DOM (превью/печать) |
| Фасад | `convert.ts` | `toMarkdown`/`fromMarkdown`/`convert(from,to)` над MD-пивотом |
| Реактивность | `composables/useConverter.ts` | трёхсторонняя синхронизация bb/md/html, `preview` = санитизированный HTML |
| Bitrix24 | `composables/useB24.ts`, `useB24Rest.ts`, `utils/b24-entity.ts` | init JSSDK (`actions.v2`), REST load/save задач/CRM/Ленты |
| Экраны | `pages/index.vue` (три-форматный редактор), `install.vue`, `widget/im-textarea.vue` | UI + плейсменты |

Полное описание слоёв, конвенций и «что нельзя трогать» — в [`../CLAUDE.md`](../CLAUDE.md).

## Что сделано

**Конвертер и UI**
- Ядро BBCode ⇄ Markdown ⇄ HTML + живое превью, печать (скрытый iframe → `window.print()`), allow-list HTML-санитайзер.
- Богатые теги round-trip через `<span data-bb-*>`-carrier: стилевые `[color]`/`[size]`/`[font]`, упоминания `[USER]`/`[DEPARTMENT]`, интерактивные теги чата `[SEND]`/`[PUT]`/`[CALL]` (официальный формат бот-сообщений Bitrix24, **issue #88 / PR #104**).
- Вставленный raw-HTML не протекает — конвертится в BBCode, а не в текст.
- Виджет `IM_TEXTAREA` (чтение/вставка в чат), install-flow, единый бренд-стиль с конвертером валют, тёмная тема.
- REST load/save: задачи (`DESCRIPTION` ±BBCode-флаг), CRM-комментарии (`COMMENT`), посты Ленты (`DETAIL_TEXT`/`POST_MESSAGE`).

**Платформа и качество**
- Обновление до актуальных версий: `@bitrix24/b24jssdk` 2.0, `@bitrix24/b24ui-nuxt` 2.9 (+ Nuxt/Vue/Tailwind/markdown-it). Совместимость с `actions.v2` сохранена.
- Постоянная визуальная проверка (Playwright e2e в CI: функциональные ассерты + dark-mode contrast-guard).
- **293 юнит-теста** (vitest) — обе стороны конвертации, HTML, санитайзер, roundtrip, парсер (perf-регресс/DoS-guard), REST-таймаут, фичи. CI-гейт зелёный.
- Решение по ретраям REST: свой retry в `useB24Rest` **не добавляем** — HTTP-слой SDK уже ретраит транзиентные сбои (**PR #106**, зафиксировано комментарием + guard-тестом).

**Продуктовые фичи (код готов, ждут активации владельцем)**
- Яндекс.Метрика на standalone (iframe-safe, gated `NUXT_PUBLIC_YANDEX_COUNTER_ID`) — **PR #100**.
- «Сообщить о неверной конвертации» (opt-in, приватный воркер, gated `NUXT_PUBLIC_FEEDBACK_URL`) — **PR #101**.
- Попап «оцените приложение» в Маркете (portal-only, троттлинг, gated `NUXT_PUBLIC_MARKETPLACE_SLUG`) — **PR #102**.

(Опция деплоя Bitrix24 Vibecode «Black Hole» — концепт, **PR #103**; см. § Деплой.)

**Безопасность и гигиена зависимостей**
- Закрыты 4 high Dependabot-алерта через `pnpm.overrides` (**PR #105**) — временный security-floor, снимаем по мере бампа родителей.
- Override `linkify-it` **снят** (markdown-it 14.3 сам требует `^5.0.2`, **PR #110**). Остаются `brace-expansion@2`/`@5` + `svgo` (снимутся после бампа nuxt / dev-tooling).
- Рутинный рефреш зависимостей: vue/tailwind/b24icons/@unhead (**#107**), eslint/openai/tsx (**#108**), markdown-it 14.3 (**#110**), @types/node 26 (**#111**), GitHub Actions setup-node@v7/github-script@v9/checkout@v7 (**#93**).
- reporting-kit (отчёты в Telegram) — файлы и проверки на месте, ждёт боевые токены.
- Документация консолидирована: состояние проекта — в этой карте, процесс работы — в [`PROCESS.md`](PROCESS.md); избыточные разрозненные доки (план/тестирование/деплой-опция/TODO) удалены, их актуальное содержимое перенесено сюда.

## Деплой

Три таргета (подробные шпаргалки — в [`../README.md`](../README.md) § Развёртывание):

| Таргет | Где живёт | Публичный IP | Когда |
|---|---|---|---|
| GitHub Pages (`deploy.yml`) | `*.github.io` | да | публичное демо / standalone (не канон) |
| **Docker/GHCR + nginx (`deploy-docker.yml`)** | свой сервер | да | **канонический контур** (self-host, свой домен) |
| **Vibecode «Black Hole»** (📝 концепт) | VM в облаке Б24 клиента | **нет** | «всё внутри портала клиента» |

**Vibecode «Black Hole»** — изолированная VM, которую Bitrix24 поднимает в облаке
клиента и управляет по REST; наружу не светится, портал достаёт её по туннелю.
Кода не требует (тот же статичный бандл: раздать `dist/` статик-сервером + отдать
порталу URL туннеля); активируется по решению владельца при доступе к Vibecode.
Точные REST-шаги фиксируются после первого прогона в реальном контуре.

**Решение №0 (принято владельцем 2026-07-24): канонический контур — Docker/nginx.**
Вся гигиена деплоя (CSP/security-заголовки/smoke) живёт на nginx-контуре и
приоритетна. GitHub Pages остаётся публичным демо/standalone (тот же бандл, без
серверных заголовков). Оба контура теперь деплоятся **только после зелёного CI**
(гейт `workflow_run:[ci]` + `conclusion==success` в обоих workflow; ручной
`workflow_dispatch` — обход для rollback; чекаут пинится на прошедший CI коммит).
